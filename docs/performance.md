## 描画が接続された後の測定手順

品質 low、shader vanilla、影なし、brightness 0.5、timeOfDay 6000、blockLight 有効、viewport 1280×720、deviceScaleFactor 1。視点は位置 `size × 1.8`、注視点 `size / 2`、FOV 50度（現在の雛形と同じ）で開始する。

アセット展開済み・ブラウザキャッシュなしの初回表示時間（要求開始からアセット・メッシュ・光の準備完了まで）、安定後10秒のfps、常駐面数、ブラウザのピークメモリを各sceneで3回測り中央値を残す。プロセスRSSとGPUメモリは区別する。#1 はメッシュ・光が未実装のため、初回描画・面数・fps は未測定。境界箱の描画をブロック描画の測定として扱わない。

未達時の品質低下順は viewer.md に従い、シェーダー → 影 → AO → 描画距離。representative の固定視点の見た目と全4版の確認はメッシュ・特殊描画の接続後に実施する。

RSS は別プロファイルの msedge / chrome / chromium プロセスの WorkingSet64 を準備完了後の10秒に約1秒間隔で合算した標本最大値。共有ページの重複を含み、初回構築中のピークと専用GPUメモリ（VRAM）は未測定。JSヒープとは異なる量である。GPUへの配列複製もあるため、メッシュ配列の値だけで使用メモリを判断しない。約180fpsはこの環境のフレーム周期の上限に近く、内蔵GPUの目標達成や余力の保証には使わない。

全場面がlowの200万面未満で、今回の固定場面では距離制限は発動しない。予算超過・カメラ移動で近いチャンクへ入れ替える処理と geometry.dispose は、同じ実装へ小さい予算を渡すテストで確認した。地形・地下は初回3秒の目安を超えた。今回だけで性能目標の達成とはせず、光・特殊描画の接続後、内蔵GPUでの測定と初期構築中のピークメモリ確認が必要。

### 代表場面の目視・操作確認

同日、ヘッドレス Edge の3視点（全景、階段〜ドアの北側拡大、ログ〜chorus plant の北側拡大）を撮影し、画像を担当者が確認した。カメラ・注視点は scripts/benchmark-mesh.mjs の views で固定する。

- 階段の段差と北向き、柵の柱と東西の腕、ガラス板の薄い形状と透明部分、上下ドアの対応を確認。
- X軸ログの端面、柵・ガラス板・chorus plant の multipart、位置から選んだ chorus plant の形状、葉のアルファ抜きを確認。重みの反映・位置ごとの再現性・uvlock の部分UVは自作モデルによるテストでも確認。
- 断面上限Y=0では1,120面、単一階Y=1では135面となり、ブロックの除外と切断面の復元を確認。別視点を同じカメラと OrbitControls で撮影し、`npm run smoke` ではマウスの左ドラッグ・右ドラッグ・ホイールを送って回転・移動・拡大への応答も確認。
- 2026-11-03、Issue #4 で更新した representative（SHA-256: `6f56baa9ff572bd9001defdc836d8735600b6d8b8f16582b65c74191090a2bbb`）をヘッドレス Edge で再撮影した。水・単体チェスト・左右テクスチャの2連チェスト・ベッドを確認。1回の実行で初回表示815ms、通常メッシュ1,249面、アトラス435,600 bytes、178.8fps。特殊描画を含む完成性能の保証ではない。
- 同日、代表sceneのignoredな一時コピーに溶岩1ブロックを加えたヘッドレス撮影でも溶岩を確認し、直後にfixtureを再生成した。溶岩は正式なrepresentativeには含めていない。
- 画像と Mojang の資産はリポジトリに含めない。他3版の完成版の目視確認は未実行。
