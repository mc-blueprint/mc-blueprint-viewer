# 全4版の代表ブロック目視確認（Issue #7）

2026-11-03、担当者がヘッドレスEdge 156.0.4314.58の固定sceneの画像を開いて確認した。ゲーム画面との画素一致を保証する検査ではない。

## 再現と保存先

Node 24.x / npm 11.x、Edge、公式アセットの展開が必要。Playwright 1.56.1は開発依存に固定し、ブラウザ本体はリポジトリへ保存しない。

```powershell
npm ci
npm run assets -- 1.21.11 --official
npm run assets -- 26.1.2 --official
npm run assets -- 26.2 --official
npm run assets -- 26.3 --official
node scripts/verify-still.mjs
```

jarは公式version manifestから取得し、公式SHA-1を検証して `%LOCALAPPDATA%\mc-blueprint\cache\jars\` に保存する。展開は既存のextract-assets.mjsを使用。撮影スクリプトは通常の `.dev-scenes` を上書きせず、OSの一時ディレクトリ `viewer-still-*` へ各版の `iso` / `front` / `top` と `detail-west` / `detail-east`（各5枚、計20枚）、sceneと `results.json` を保存する。実行末尾に絶対パスを表示する。画像・Mojangの資産はGitへ追加しない。

sceneは `makeScene('representative', undefined, version)`（fixture-v1にIssue #7の溶岩を追加した配置）を使用。32×16×16、low、vanilla、影なし、brightness=0.5、timeOfDay=6000、blockLight有効、1600×900、倍率1。固定視点の計算は [still.md](still.md)、拡大カメラは `verify-still.mjs` に固定した。西側拡大は位置(9,5,-8)・注視点(8,1.2,3)、東側拡大は(23,5,-9)・(23,1.2,3)。

## 目視で見つけて修正した点と限界

- 26.2 / 26.3ではベッドが通常モデルへ移行し、従来の `entity/bed/red.png` の取得が404になった。`usesBlockModel`で版ごとに通常モデルへ接続し、特殊描画との二重描画を防いだ。sceneのrender指定・ハッシュは書き換えない。
- チェストの側面UVが90度ずれ、胴・蓋の領域も混ざっていた。各部品のUVと向きを分け、左右半分の寸法をつなぎ、留め具を加えた。旧ベッドのUV領域・脚も修正した。
- 特殊描画を一律に半透明・深度書込み無効としていたため、チェストやベッドの内部面が上から重なった。通常描画と同じ不透明・切抜き・半透明のmaterial groupへ分けて解消した。所有ブロック座標も整数に保つ。
- 同一サイズへのcanvas再設定を省き、生CDP撮影のcompositor待ち不足はPlaywrightのscreenshotで解消した。準備完了後の背景だけの画像を全20枚のPNG画素検査で検出する。
- 流体は水平な高さの近似で、流向・四隅の傾き・アニメーションは未対応。半透明は面ごとの厳密なソートではない。チェストは閉じた状態だけを対象とする。これらはゲーム画面との同一性を保証しない既存の描画範囲。

同じ実ブラウザ検証で、3視点・3プリセット、UI非表示、マウス操作による固定視点の保持、不正な視点・プリセットでalertかつreadyでないことも確認する。
